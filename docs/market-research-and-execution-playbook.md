## 1. 실제 오디션 현장 워크플로우 & 심사관 행동 패턴 심층 분석

### 1.1 기획사 신인개발팀(Casting Team)의 실제 하루 업무
* **일일/월간 접수 규모:**
  * 중견 기획사(스타쉽, 큐브, FNC, RBW, 판타지오 등): 월평균 **1,500 ~ 3,000건** 영상 접수
  * 중소/신생 기획사: 월평균 **300 ~ 800건** (공개 오디션 공고 기간에는 3,000건 이상 폭증)
  * 상시 접수 인입 채널: 기획사 공식 오디션 이메일(60%), 구글폼/네이버폼(25%), 카카오톡 채널/인스타그램 DM(15%)
* **실무자의 실제 검토 루틴 (현장 병목의 본질):**
  1. **다운로드 및 링크 만료 지옥:**  
     지원자들의 영상이 네이버 대용량 첨부(30일 후 자동 만료), 구글 드라이브(권한 미부여로 열람 불가), 카카오톡 압축파일 등으로 제각각 도착. 1건당 다운로드 및 대기 시간에만 1~2분 소요.
  2. **아이폰 고효율 비디오(HEVC/MOV) 코덱 오류:**  
     지원자의 80% 이상이 아이폰으로 촬영하여 `.mov` 포맷으로 제출하나, 사내 윈도우 PC 기본 미디어 플레이어에서 재생되지 않아 별도 코덱 설치나 수동 인코딩 프로그램을 거쳐야 함.
  3. **3초 스크리닝 룰 (The 3-Second Rule):**  
     * 실무자 인터뷰 공통 증언: *"영상 전체(1~2분)를 다 보는 경우는 1% 미만입니다. 첫 화면 구도와 마스크(얼굴/비율), 보컬 첫 소절(톤/피치), 댄스 첫 박자(그루브)만 확인하면 3~5초 안에 다음 영상으로 넘어갑니다."*  
     * 그러나 이메일/드라이브 환경에서는 '다음 사람'을 보려면 다시 폴더를 열고 파일을 더블클릭해야 하므로 물리적 피로도가 극대화됨.
  4. **수작업 엑셀 복사·붙여넣기:**  
     * 유망한 후보가 발견되면 엑셀 시트에 `[이름, 생년월일, 키, 몸무게, 지역, 연락처, 파일링크, 1차평가 메모]`를 수작업 타이핑.
  5. **주간 캐스팅 보고 회의 (Executive Review):**  
     * 매주 금요일, 신인개발팀장·총괄이사·대표가 모여 1차 선발된 10~20명의 영상을 대형 TV나 빔프로젝터로 함께 시청.
     * 회의 준비를 위해 담당 막내 매니저는 목요일 밤새 영상을 잘라 하나의 폴더에 모으거나 PPT 슬라이드에 링크를 붙이는 단순 영상 편집 야근을 반복.

## 2. Enter-AX 실제 서비스 구현 필수 스펙 & 비디오 엔지니어링 파이프라인

발표용 데모가 아닌, **실제 기획사가 업무에 즉시 도입할 수 있는 프로덕션 기능 스펙**입니다.

```
[지원자 스마트폰 브라우저] 
         │ (Direct Pre-signed URL / Multipart 청크 업로드)
         ▼
[Cloudflare R2 Object Storage] ──(Webhook Event)──> [FFmpeg Transcode Worker]
• 원본 영상 보관 (Egress $0)                         • 세로/가로 자동 인식 720p H.264
                                                     • faststart 플래그 (0초 스트리밍)
                                                     • 3초 무음 WebP 미리보기 생성
                                                     • 보컬/댄스 시작점(묵음 스킵) 감지
                                                                  │
                                                                  ▼
[기획사 신인개발팀 웹보드] <──(Cloudflare CDN 스트리밍)── [Enter-OS Screening Kanban]
• J/K 키보드로 0.1초 만에 넘겨보는 3초 뷰어            • MediaPipe 33관절 박자 싱크 보조
• 팀원 비공개 별점 & 코멘트 격리                       • 주간 임원 회의용 9:16 숏폼 원클릭 출력
• 사번/IP 워터마크 자동 오버레이                      • 합격/불합격 상태별 자동 SMS 발송
```

### 2.1 지원자 접수 파이프라인 (Intake Engine)
* **모바일 무설치 웹 폼 (Responsive Web):**
  * 지원자의 80% 이상이 스마트폰으로 접근하므로 반응형 웹 필수.
  * 필수 수집 필드: 이름, 생년월일, 성별, 키/몸무게, 국적, 거주지, 본인/보호자 연락처, SNS ID(인스타그램/틱톡).
  * 사진 업로드: 전신 사진 1장 + 상반신 정면(노메이크업/무보정) 1장 필수 강제.
* **대용량 다이렉트 업로드 (Zero Memory Spike):**
  * 모바일 4K/FHD MOV 파일(500MB~2GB)을 웹 서버를 거치지 않고 브라우저에서 **Cloudflare R2 Pre-signed URL**로 직접 청크 업로드.
  * 서버 메모리 고갈 방지 및 모바일 네트워크 단절 시 이어올리기(Multipart Upload) 지원.

### 2.2 비디오 엔지니어링: 프로덕션 FFmpeg 명령어 스펙
실제 모바일 지원 영상은 90%가 세로(Portrait: 9:16) 영상이고, 10%가 가로(Landscape: 16:9) 영상입니다. 이를 완벽히 처리하는 검증된 FFmpeg 스펙입니다:

1. **세로/가로 자동 감지 웹 스트리밍 인코딩 (`-movflags +faststart` 필수):**
   ```bash
   # 세로 영상이면 가로폭 720 기준, 가로 영상이면 세로폭 720 기준으로 비율 자동 유지
   # -movflags +faststart: MP4 파일의 메타데이터(moov atom)를 파일 맨 앞으로 이동시켜
   # 전체 파일을 다 받지 않고 첫 1초 만에 브라우저에서 즉시 스트리밍 재생되도록 보장
   ffmpeg -i input.mov \
     -vf "scale='if(gt(iw,ih),-2,720)':'if(gt(iw,ih),720,-2)'" \
     -c:v libx264 -preset fast -crf 23 -pix_fmt yuv420p \
     -c:a aac -b:a 128k -ar 44100 -ac 2 \
     -movflags +faststart output.mp4
   ```
2. **스크리닝 보드 마우스 오버용 3초 무음 WebP 미리보기 추출:**
   ```bash
   # 영상 3초 지점부터 3초간 10fps로 고화질 애니메이션 WebP 생성 (음성 제거 -an)
   ffmpeg -ss 00:00:03 -t 3 -i output.mp4 \
     -vf "fps=10,scale='if(gt(iw,ih),-2,360)':'if(gt(iw,ih),360,-2)':flags=lanczos" \
     -c:v libwebp -lossless 0 -q:v 70 -loop 0 -an preview.webp
   ```
3. **오디오 묵음 구간 감지 및 첫 소절 자동 점프:**
   * 지원자가 노래 시작 전 뜸 들이는 5~10초의 빈 구간을 FFmpeg `silencedetect` 필터로 감지하여, 심사관이 영상 오픈 시 **"첫 음성/댄스 시작 지점으로 자동 스킵"** 버튼 제공.

### 2.3 신인개발팀 전용 스크리닝 칸반 CRM (Enter-OS)
* **초고속 단축키 기반 훑어보기 (Speed Screening):**
  * `Space`: 재생/일시정지
  * `J` / `K`: 이전/다음 지원자 즉시 전환 (버퍼링 없이 0.1초 내 렌더링)
  * `1`~`5`: 별점 매기기
  * `P`: 1차 합격(Pass) 이동 / `D`: 불합격(Drop) 이동
* **내부 평가 데이터 암호화 & 권한 분리:**
  * 같은 회사 내에서도 '인턴 매니저의 코멘트'와 '팀장의 최종 결정'을 분리 관리.
* **회의용 9:16 숏폼 및 원페이지 PDF 자동 생성:**
  * 합격 후보 10명을 선택하고 [회의 자료 생성] 클릭 시:
    * 영상의 하이라이트 15초를 9:16 세로 영상으로 크롭하고 하단에 `[지원자명 | 2009년생 | 168cm | 보컬 지원]` 자막 오버레이 자동 합성.
    * 임원 회의용 요약 PDF 리포트(QR코드로 영상 즉시 재생 연결) 자동 출력.
* **사내 영상 유출 방지 워터마크:**
  * 웹 플레이어 화면 전체에 **"열람자 사번, 사내 접속 IP, 현재 시각"이 반투명 오버레이**되어 불법 화면 녹화 및 외부 유출을 원천 방지.

## 3. 실제 서비스 배포 아키텍처 & 유닛 이코노믹스 (원가 분석)

### 3.1 권장 프로덕션 인프라 아키텍처
* **웹 프론트엔드 & 관리자 콘솔:** Next.js 14 App Router (Vercel Enterprise 또는 AWS 서울 리전 `ap-northeast-2`).
* **영상 스토리지 & CDN:** **Cloudflare R2 + Cloudflare CDN**
  * *핵심 선정 사유:* AWS S3는 비디오 스트리밍 시 Egress(데이터 송출료)가 GB당 약 $0.09로 치명적인 비용 발생. **Cloudflare R2는 Egress 수수료가 $0**이므로 고화질 영상 수천 개를 기획사가 반복 재생해도 트래픽 비용이 0원.
* **데이터베이스:** AWS RDS PostgreSQL 또는 Supabase (Row Level Security로 기획사별 테넌트 데이터 완벽 격리).
* **미디어/AI 인퍼런스 워커:** Python Celery / FastAPI Worker on GPU 인스턴스 (AWS g4dn.xlarge 또는 RunPod/Lambda Labs 서버리스 GPU).

### 3.2 유닛 이코노믹스: 지원자 1인당 원가 구조 (Unit Economics)

| 비용 항목 | 단가 및 산출 기준 | 지원자 1인당 원가 (KRW) | 비고 |
| :--- | :--- | :---: | :--- |

## 4. 국내 법적 컴플라이언스 (개인정보보호법·대중문화예술산업발전법) 실무 가이드

### 4.1 만 14세 미만 아동의 개인정보 수집 규정 (개인정보 보호법 제22조의2)
1. **법정대리인(부모) 동의 의무 (제22조의2 제1항):**
   * 아이돌 지망생의 30~40%는 초등학교 고학년~중학교 1학년(만 14세 미만)입니다.
   * 지원자가 생년월일을 입력했을 때 만 14세 미만일 경우, 즉시 **"보호자 휴대폰 번호 입력 -> PASS/알림톡 본인인증 -> 법정대리인 동의 완료"** 전까지 영상 제출 버튼이 활성화되지 않도록 시스템을 구현해야 합니다.
2. **동의 확인 방법 (동법 시행령 제17조의2):**
   * 법정대리인의 휴대폰 본인확인 또는 카드 인증 등 법정대리인임을 확인할 수 있는 합리적인 방법을 사용하여 동의 사실을 확인해야 합니다.
3. **최소한의 정보 수집 (제22조의2 제2항):**
   * 법정대리인 동의를 받기 위한 최소 정보(성명, 연락처)는 별도 동의 없이 아동으로부터 직접 수집할 수 있습니다.

### 4.2 오디션 영상 보관 및 파기 규정 (개인정보 보호법 제21조)
* **목적 달성 후 지체 없는 파기 (제21조 제1항):**
  * 오디션 심사 종료 후 원칙적으로 지체 없이(통상 5일 이내) 파기해야 합니다. 위반 시 **3천만 원 이하의 과태료** 부과 (제75조 제2항 제4호).

* **복구 불가능한 영구 파기 (제21조 제2항):**
  * 탈락자의 동의 미체크 영상은 **심사 완료 후 30일/90일 경과 시 암호화 파기(Cryptographic Erasure)** 스케줄러를 자동 실행하여 복원이 불가능하도록 영구 삭제.

### 4.3 대중문화예술산업발전법 (2026.01.01 시행 최신 개정안) 반영
