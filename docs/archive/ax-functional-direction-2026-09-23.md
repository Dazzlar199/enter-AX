# 엔터사 AX 기능 방향 조사 (2026-09-23)

목표: 기획사 캐스팅·A&R 담당자가 **실제 업무에 매일 쓰는** 업무 자동화가 되려면 무엇이 더 필요한지 정리한다.
방법: 업무 자동화 도구(n8n), 채용 관리 도구(Greenhouse), 캐스팅 플랫폼(Casting Networks·Backstage), 국내 규제(개인정보보호법·AI 기본법), 국내 메시징(카카오 알림톡)을 조사하고 현재 코드와 대조했다.

## 1. 지금 되는 것 / 안 되는 것

| 영역 | 현재 상태 (코드 기준) |
| --- | --- |
| 자동화 편집 | 단계를 끌어다 놓고 선으로 연결, 순환 연결 차단, 단계별 설정·입력·출력 보기, 결과 미리보기 (`src/components/agency/workflow-editor/`) |
| 실행 | 단계 순서대로 실행, 승인 단계에서 멈춘 뒤 재개, 반려 시 이후 단계 건너뜀 (`src/features/workflows/engine.ts`) |
| 서버 실행 단계 | 외부 데이터 가져오기(API 호출, 내부망 차단·15초·1MB 제한), AI 요약(로컬 Ollama), Slack 전송 (`src/server/workflows/`) |
| 앱 데이터 단계 | 지원자 가져오기, 내부 검토로 옮기기, 커뮤니티 공지 작성 |
| 저장 | **브라우저(localStorage)에만 저장.** 서버 저장·팀 공유 없음 (`src/features/workflows/store.ts`) |
| 권한 | **기획사 로그인 없음.** 서버 실행 API는 출처 확인과 IP당 분당 60회 제한뿐 (`src/app/api/v1/workflows/execute/route.ts`) |
| 시작 방법 | 사람이 누르는 ‘직접 시작’만 있음. 새 지원서 도착·정해진 시각 같은 자동 시작 없음 |
| 실행 기록 | 화면을 닫으면 사라짐. 누가 언제 무엇을 승인했는지 남지 않음 |
| 비밀값 | Slack Webhook·API 키를 단계 설정에 그대로 입력하고 브라우저에 평문 저장 |
| 미성년자 | 지원자가 ‘미성년’ 체크박스를 스스로 표시하고 동의 체크만 하면 통과 (`src/features/talent/validation.ts`) |

## 2. 조사 요약

### 업무 자동화 도구가 실제 운영에서 갖추는 것 (n8n)
- 단계별 **재시도**(외부 API 호출은 3~5회, 5초 간격 권장)와, 실패 시 따로 도는 **오류 처리 흐름**.
- **실행 기록**을 남겨 실패 원인을 추적하되, 입력·출력에 개인정보나 비밀값이 들어가므로 보존 기간을 둔다.
- 비밀값은 단계에 직접 넣지 않고 **자격 증명 보관함**에 저장한다.
- **사람 승인(Human-in-the-loop)**: 흐름을 멈추고 지정한 사람이나 채널에 검토 요청을 보낸 뒤, 승인·반려·기한 만료 중 하나가 되면 이어서 진행한다. AI가 도구를 실행하기 전에 사람 승인을 강제하는 방식도 있다.

### 채용 관리 도구의 핵심 (Greenhouse)
- 직무별 평가 기준을 정하고, 심사자마다 같은 질문과 **평가표(scorecard)**로 평가해 느낌에 의존한 판단을 줄인다.
- 결정 전에 심사위원 평가를 모아 본다.
- 이름·이력을 가린 **블라인드 1차 검토**, 편향 표현 경고.
- 제안서 승인 절차, 단계별 전환율·채용 소요 시간 리포트.

### 캐스팅 플랫폼의 흐름 (Casting Networks · Backstage)
- 지원자 목록에서 바로 **셀프테이프(추가 영상) 요청**: 대본·지시사항·마감일을 붙여 보내고, 제출 상태를 실시간으로 추적한다.
- 하트/X 버튼으로 **관심·제외 폴더**에 바로 분류하고, 여러 명을 한 번에 처리하는 **일괄 작업**(메시지, 셀프테이프 요청, 제안·확정 폴더 이동).
- 지원자도 자기 지원 상태(검토 중 등)를 볼 수 있다.

### 국내 규제
- **개인정보보호법 제22조의2:** 만 14세 미만 아동의 개인정보를 처리하려면 법정대리인 동의를 받고, **동의했는지 확인**해야 한다. 확인 방법은 문자메시지, 신용카드, 본인인증 등이다. 위반하면 5년 이하 징역 또는 5천만 원 이하 벌금이다.
- **AI 기본법 (2026-01-22 시행):** 고영향 인공지능 영역에 **"채용, 대출 심사 등 개인의 권리·의무 관계에 중대한 영향을 미치는 판단 또는 평가"**가 포함된다. 의무 주체에는 남이 만든 AI를 이용해 서비스를 제공하는 회사도 들어간다. 계도기간이 끝나면 시정명령 대상이 된다. 오디션 심사에 AI 비교 자료를 제공하는 기능이 여기에 해당하는지는 **법률 검토가 필요하다**.

### 국내 메시징 (카카오 알림톡)
- 채널을 추가하지 않은 사용자에게도 보낼 수 있다. 단 **정보성 메시지만** 가능하다(사용자 행동에 대한 직접 피드백).
- 카카오가 **승인한 템플릿으로만** 발송할 수 있다. 템플릿 심사는 영업일 기준 2~3일이 걸린다.
- 적법하게 수집한 전화번호만 사용할 수 있다.
- 접수 확인, 결과 통지, 미팅 일정 안내 용도에 맞는다.

## 3. 방향 제안

우선순위: **P0** = 유료 도입 전에 반드시 필요 / **P1** = 캐스팅 실무에서 매일 쓰는 가치 / **P2** = 차별화

### P0 — 상용 운영의 바닥

| # | 기능 | 이유 | 범위 |
| --- | --- | --- | --- |
| P0-1 | 기획사 계정·역할 권한 | 워크플로·지원자 자료는 기획사별로 분리돼야 함. 현재 실행 API가 사실상 공개 상태 | 역할: 관리자 / 캐스팅 담당 / 열람 전용. 기존 `tenants`·`tenant_memberships` 테이블 활용 |
| P0-2 | 자동화·실행 기록 서버 저장 | 팀 공유, 기기 변경, 감사 대응 | `WorkflowStore` 인터페이스를 DB 저장으로 교체, 실행 기록은 보존 기간을 두고 저장 |
| P0-3 | 자격 증명 보관함 | Slack Webhook·API 키가 브라우저에 평문 저장됨 | 서버 암호화 저장, 단계에서는 이름으로만 선택 |
| P0-4 | 서버 실행 엔진과 자동 시작 | 사람이 화면을 열어야만 돌아가면 자동화가 아님 | 새 지원서 도착(이벤트), 정해진 시각(스케줄), 외부 호출(웹훅) 시작. 작업 대기열과 서버 작업자 필요 |
| P0-5 | 재시도·오류 알림 | 외부 API는 실패함 | 단계별 재시도 횟수·간격, 실패 시 담당자 알림 |
| P0-6 | 승인 요청 전달·기한 | 지금은 승인하려면 편집기를 열어야 함 | Slack·이메일·알림톡으로 승인 요청, 기한이 지나면 상위 담당자에게 넘김, 승인자·시각 기록 |
| P0-7 | 미성년자 법정대리인 동의 확인 | 현재 자기 표시 체크박스만 있음. 형사처벌 조항 | 만 14세 미만은 법정대리인 문자·본인인증 확인, 확인 전 비공개. 생년월일로 자동 판정 |
| P0-8 | AI 기본법 대응 기록 | 채용성 판단이 고영향 영역 | AI 결과의 근거(무엇을 비교했는지) 표시, 사람 결정 기록, 위험관리 문서. **법률 검토 선행** |

### P1 — 캐스팅 실무 기능

| # | 기능 | 참고 | 설명 |
| --- | --- | --- | --- |
| P1-1 | 오디션 공고 → 지원서 → 자동 접수 | 캐스팅 플랫폼, IR 검수 A1 | 공고를 만들면 지원서 링크가 생기고, 제출하면 ‘새 지원서’ 시작 조건이 실행됨 |
| P1-2 | 셀프테이프(추가 영상) 요청 | Casting Networks, Backstage | 지원자에게 지정 안무·곡과 마감일을 보내고, 제출 여부를 추적. 제출 시 자동으로 비교 단계 연결 |
| P1-3 | 일괄 작업 | Backstage 일괄 작업 | 여러 지원자를 한 번에 단계 이동, 연락, 셀프테이프 요청 |
| P1-4 | 심사 평가표 | Greenhouse 평가표 | 보컬·댄스·표현력·성장 가능성 등 수행 기준으로 심사위원별 평가와 메모, 합산 보기. **외모 점수 항목은 두지 않음** |
| P1-5 | 블라인드 1차 검토 옵션 | Greenhouse 익명 검토 | 보컬 1차는 이름·사진을 가리고 음원만 듣는 모드 |
| P1-6 | 결정권자 공유 링크 | 캐스팅 '셀렉트' 공유 | 대표·프로듀서에게 추린 지원자만 보이는 읽기 전용 링크, 만료일 지정 |
| P1-7 | 알림톡 연동 단계 | 카카오 비즈메시지 | 접수 확인·결과 통지·미팅 안내. 템플릿 심사 흐름을 설정 화면에 반영 |
| P1-8 | 일정 잡기 | ATS 면접 일정 | 미팅·2차 오디션 시간대 제시와 지원자 선택, 캘린더 연동 |
| P1-9 | 지원자 쪽 진행 상태 | 캐스팅 플랫폼 | 지원자가 ‘검토 중 / 추가 영상 요청 / 결과’ 상태를 앱에서 확인 |

### P2 — 차별화

| # | 기능 | 설명 |
| --- | --- | --- |
| P2-1 | 자료 자동 점검 | 영상 길이·해상도·얼굴 인식·음성 구간을 확인해 누락·불량 자료를 접수 단계에서 돌려보냄 |
| P2-2 | 중복 지원 탐지 | 같은 사람이 이름·연락처를 바꿔 여러 번 지원한 경우 표시 |
| P2-3 | 업계 자동화 템플릿 | 공개 오디션 1차 정리, 주간 A&R 브리핑, 컴백 숏폼 준비 등 바로 쓰는 흐름 |
| P2-4 | 성과 지표 | 접수 → 1차 통과 → 미팅 전환율, 지원자 1명당 검토 시간. 파일럿의 ‘검토 시간 비교’를 제품이 직접 측정 |
| P2-5 | 실행 비용 표시 | AI 요약·영상 분석 호출 수와 예상 비용을 실행 전에 보여줌 |

## 4. 추가할 단계(노드) 후보

| 분류 | 단계 | 비고 |
| --- | --- | --- |
| 시작 방법 | 새 지원서 도착, 정해진 시각, 외부 호출(웹훅), 셀프테이프 제출 | 서버 작업자 필요 (P0-4) |
| ENTER—AX | 셀프테이프 요청, 단계 이동(임의 단계), 평가표 요청, 공유 링크 만들기 | P1 |
| 데이터 처리 | 중복 제거, 정렬·상위 N명, 분기(조건별 다른 경로), 기다리기(시간) | n8n 기본 단계와 대응 |
| AI | 춤·음정 비교(기존 분석 API 연결), 자료 점검, 요약 근거 표시 | 기존 `/api/talent/compare-*` 재사용 |
| 외부 연동 | 카카오 알림톡, 이메일, Google Sheets 쓰기, Google Calendar 일정 | 자격 증명 보관함 필요 (P0-3) |

## 5. 권장 순서

1. **P0-1 · P0-2 · P0-3:** 계정·권한, 서버 저장, 자격 증명. 이게 없으면 다른 기능을 유료로 팔 수 없다.
2. **P0-7:** 미성년자 동의 확인. 법적 위험이 가장 크고, 오디션 지원자 상당수가 10대다.
3. **P0-4 · P1-1:** 서버 실행과 '새 지원서 도착' 시작, 오디션 공고. 여기부터 진짜 '자동'이 된다.
4. **P0-6 · P1-7:** 승인 요청을 Slack·알림톡으로 보내기. 담당자가 편집기를 열지 않아도 된다.
5. **P1-2 · P1-3 · P1-4:** 셀프테이프, 일괄 작업, 평가표. 캐스팅 실무의 매일 업무다.
6. **P0-8:** AI 기본법 대응은 법률 검토 결과에 따라 병행한다.

## 6. 확인이 필요한 질문

1. 오디션 심사에 쓰는 AI 비교 자료가 AI 기본법의 '채용 등 판단·평가' 고영향 영역에 해당하는가? (법률 자문)
2. 연습생 계약 전 오디션 단계가 '채용'으로 해석되는가?
3. 지원자 연령 분포(만 14세 미만 비중)는 얼마인가? P0-7의 긴급도를 정한다.
4. 파일럿 기획사가 이미 쓰는 메신저는 무엇인가(Slack, 카카오톡, 이메일)? P0-6 · P1-7의 우선 연동 대상을 정한다.
