## 0. 한 장 요약

**정의** — ENTER—AX의 AX는 기획사의 **오디션 운영, A&R 데모 수급, 홍보 콘텐츠 제작**을 한 곳에서 처리하는 업무 도구다. 반복 작업은 자동화하고, 합격·게시·연락 같은 결정은 반드시 담당자가 승인한다.

**지금의 위치**
- 화면과 핵심 로직은 동작한다: 업무 자동화 편집기, 승인 단계, 서버 실행 단계, 춤·음정 비교, 콘텐츠 처리.
- 하지만 **계정, 서버 데이터, 자동 시작, 알림, 저장소가 없어 실제 기획사가 매일 쓸 수는 없는 상태**다.

**만들 것 (우선순위순)**
1. **기반:** 기획사 계정·권한 → 지원자 데이터와 영상의 서버 저장 → 서버 실행 엔진(자동 시작·재시도·실행 기록·승인 요청 전달) → 미성년자 법정대리인 확인
2. **오디션 운영 (파일럿 핵심):** 공고·지원서 → 자료 자동 점검 → 심사 평가표 → 셀프테이프 요청 → 일괄 처리 → 알림톡 결과 통지 → 일정 잡기
3. **A&R·콘텐츠:** 데모 수신함(곡 리드 발송, 중복 탐지, 청취 평가) → 업로드 기반 숏폼 → YouTube 게시(이후 Instagram·TikTok)
4. **측정:** 지원자 1명당 검토 시간, 접수부터 결과 통지까지 걸린 시간. 파일럿 성과를 제품이 직접 잰다.

**바로 결정할 것**
- YouTube 영상 다운로드 기능(yt-dlp) 제거. 약관 위반 소지가 있다.
- AI 기본법 법률 검토 착수
- 실행 엔진 선택: Postgres 기반 대기열 권장
- 동영상 처리 서버의 호스팅 방식

## 1. 사용자와 업무

| 사용자 | 하는 일 | 지금 겪는 문제 | 빈도 |
| --- | --- | --- | --- |
| **캐스팅 담당** (신인개발팀) | 오디션 공고, 지원서 접수, 1차 검토, 추가 영상 요청, 미팅·카메라 테스트 일정, 결과 통지 | 메일·폼·드라이브·시트·메신저에 자료가 흩어짐. 누락 자료 확인과 결과 통지가 수작업 | 매일 |
| **신인개발팀장 / 결정권자** | 추린 지원자 확인, 최종 판단, 팀 의견 취합 | 판단 근거가 대화방에 흩어짐. 누가 왜 통과시켰는지 남지 않음 | 주 1~3회 |
| **A&R 담당** | 곡 리드 작성, 작곡가 네트워크에 발송, 데모 수십~수백 곡 수신·청취, 수록곡·타이틀곡 선정 | 데모가 메일·링크로 쏟아지고, 같은 곡이 중복으로 들어옴. 청취 의견 공유가 어려움 | 앨범 주기마다 집중 |
| **콘텐츠·SNS 담당** | 무대·연습 영상에서 숏폼 제작, 자막, 채널별 게시 | 편집 반복, 채널별 규격 차이, 게시 전 승인 절차 | 주 여러 회 |
| **대표·관리자** | 계정·권한, 비용, 보안, 현황 | 누가 무엇을 볼 수 있는지 통제하기 어려움 | 월 단위 |
| **지원자** (B2C) | 프로필 등록, 공고 지원, 추가 영상 제출, 결과 확인 | 결과를 모른 채 기다림. 여러 회사에 같은 자료를 반복 제출 | 지원 시 |

근거: 스타쉽 공고의 전형 순서(온라인·우편 지원 → 1차 서류 → 카메라 테스트·실무진 오디션 → 최종), A&R의 곡 리드 기반 데모 수급(수십~수백 곡), YG 신인개발팀 채용 공고(연습생 일정·케어). 출처는 끝에 정리.

## 2. 핵심 업무 흐름 (시나리오)

### S1. 공개 오디션 운영 — 파일럿 1순위
```
공고 작성 → 지원서 링크 배포 → [자동] 접수 즉시 자료 점검(사진 3장·영상 길이·음성·얼굴)
→ [자동] 누락 시 지원자에게 보완 요청(알림톡) → 1차 심사: 평가표로 심사위원별 평가
→ 셀프테이프 요청(지정 곡·안무, 마감일) → [자동] 제출되면 기준 영상과 비교 자료 생성
→ [승인] 팀장이 미팅 대상 확정 → 일정 제안·지원자 선택 → 최종 심사
→ [승인] 결과 통지 발송(알림톡) → 합격자는 계약 전 단계로
```
사람이 결정하는 지점은 다음 세 곳이다: 1차 통과, 미팅 대상 확정, 결과 통지 발송.

### S2. A&R 데모 수급
```
곡 리드 작성(아티스트·콘셉트·BPM·마감) → 작곡가 네트워크에 발송(이메일)
→ 데모 수신함: 업로드 링크로 접수, 작곡가·퍼블리셔 정보 자동 기록
→ [자동] 같은 음원 중복 탐지(오디오 지문) → A&R 팀 청취 평가(평점·태그·코멘트)
→ 후보곡 보드(보류·홀드·확정) → [승인] 홀드 요청 발송 → 녹음 일정
```

### S3. 홍보 숏폼 제작·게시
```
원본 영상 업로드(자체 보유 파일) → 하이라이트 구간 후보·자막 초안
→ 편집(CapCut 초안 내보내기 또는 자체 편집) → [승인] 게시 승인
→ YouTube Shorts 게시(API) → 이후 Instagram Reels · TikTok(각 플랫폼 심사 통과 후)
```

### S4. 주간 운영 브리핑
```
매주 월 09:00 → 지원자 관리·제안·콘텐츠 현황 집계 → 지연 업무 탐지
→ AI 요약 → [승인] 팀장 확인 → Slack 또는 알림톡 공유
```

## 4. 모듈별 기능 명세

각 모듈은 **목적 · 핵심 기능 · 완료 기준**으로 적는다. 완료 기준은 파일럿 기획사가 실제로 쓸 수 있는 수준이다.

### M1. 기획사 계정·조직·권한
- 기능
  - 이메일 초대 가입
  - 역할: 관리자 / 캐스팅 / A&R / 콘텐츠 / 열람 전용
  - 기획사 인증 상태(심사 중·인증)
  - 모든 데이터를 기획사 단위로 분리. 기존 `tenants` 테이블과 행 수준 보안(RLS) 활용
- 완료 기준
  - 다른 기획사 데이터에 접근하면 403이 나고, 그 시도가 감사 로그에 남는다.
  - 열람 전용 사용자는 승인·연락·게시 버튼이 비활성이다.

### M2. 지원자 데이터·미디어 저장
- 기능
  - 지원자 프로필·동의 기록을 DB에 저장
  - 사진·영상은 **오브젝트 스토리지(S3·R2)에 브라우저에서 바로 분할 업로드**. 이어 올리기 지원(presigned multipart 또는 tus). Next.js 서버를 거치지 않는다(서버리스 요청 크기 제한 4.5MB 회피).
  - 업로드 후 서버 작업자가 트랜스코딩·썸네일을 만든다.
  - 공개 범위에 따라 서명 URL을 발급한다(기획사 전용 / 전체 공개).
- 완료 기준
  - 2GB 영상이 네트워크가 끊겨도 이어서 올라간다.
  - 인증되지 않은 기획사는 원본 URL을 얻을 수 없다.

### M3. 오디션 공고·지원서
- 기능
  - 공고 작성: 분야, 연령 조건, 필수 자료, 마감, 전형 단계
  - 공고별 지원서 링크와 QR
  - 커뮤니티 '공고' 탭에 게시(IR 검수 A1 해소)
  - 지원 시 기존 프로필 재사용(한 번 등록, 여러 공고 지원)
- 완료 기준: 공고 1건으로 지원서를 받고, 접수되면 '새 지원서' 자동 시작 조건이 실행된다.

### M4. 심사
- **자료 자동 점검:** 사진 3장, 영상 길이·해상도, 음성 구간, 얼굴 검출. 부족하면 보완 요청 초안을 만든다.
- **평가표:** 공고별 평가 기준(보컬·댄스·표현력·성장 가능성 등 수행 요소). 심사위원별 점수·메모와 합산 보기. **외모 점수 항목은 만들 수 없다.**
- **블라인드 1차:** 보컬 1차에서 이름·사진을 가리고 음원만 듣는 모드
- **셀프테이프 요청:** 지정 곡·안무·지시사항·마감일을 보내고 제출 상태를 추적. 제출되면 비교 분석을 자동 실행
- **일괄 작업:** 여러 지원자를 한 번에 단계 이동·셀프테이프 요청·결과 통지
- **공유 링크:** 결정권자용 읽기 전용 링크(추린 명단, 만료일, 열람 기록)
- 완료 기준: 지원자 100명 공고에서 1차 평가와 셀프테이프 요청을 한 화면에서 끝낼 수 있다.

### M5. 커뮤니케이션
- **알림톡:** 접수 확인, 보완 요청, 셀프테이프 요청, 결과 통지, 미팅 안내. 정보성 템플릿만 쓰고 템플릿 심사 상태를 관리한다.
- **이메일:** 알림톡 실패 시 대체, 해외 지원자용
- **일정 잡기:** 미팅·카메라 테스트 시간대를 제시하면 지원자가 선택하고, Google Calendar에 등록
- **지원자 앱 상태:** 검토 중 / 추가 영상 요청 / 미팅 / 결과
- 완료 기준: 결과 통지 발송 전 승인 단계가 강제되고, 발송 결과(성공·실패)가 지원자별로 남는다.

### M6. 업무 자동화 엔진 (서버화)
- **실행 위치:** 브라우저에서 서버로. 실행 상태를 DB에 저장해 서버가 재시작돼도 승인 대기에서 그대로 이어간다.
- **시작 방법:** 직접 시작, 새 지원서 도착, 셀프테이프 제출, 정해진 시각(cron), 외부 호출(웹훅)
- **안정성:** 단계별 재시도(외부 호출 3~5회, 간격 증가), 실패 시 담당자 알림
- **실행 기록:** 단계별 입력·출력, 소요 시간. 개인정보를 포함하므로 보존 기간(예: 30일)과 마스킹을 둔다.
- **자격 증명 보관함:** Slack·알림톡·API 키를 서버에서 암호화 저장. 단계에서는 이름으로만 고른다.
- **승인 요청 전달:** Slack 버튼, 알림톡, 이메일 링크로 승인·반려. 기한이 지나면 상위 담당자에게 넘긴다. 승인자·시각을 기록한다.
- **버전:** 저장할 때마다 버전을 남기고, 실행 중인 흐름은 시작 당시 버전으로 끝까지 돈다.
- **추가할 단계:** 분기, 기다리기, 중복 제거, 정렬·상위 N명, 알림톡, 이메일, Google Sheets 쓰기, 캘린더, 셀프테이프 요청, 평가표 요청, 비교 분석
- 완료 기준: 새 지원서 도착 → 자료 점검 → 누락 시 보완 요청(승인 후) 흐름이 사람의 개입 없이 돈다. 승인만 사람이 한다.

### M7. 분석 도구 (비동기화)
- 기능
  - 기존 MediaPipe·librosa 비교를 **작업 대기열 기반 분석 작업자**로 옮긴다. 요청은 즉시 받고, 진행률을 보여주고, 끝나면 알림
  - 결과에는 무엇을 어떻게 비교했는지(근거)를 함께 표시한다.
  - 합격·불합격 판정 문구는 만들지 않는다.
- 완료 기준: 5분짜리 영상 비교가 화면을 막지 않고, 실패하면 재시도할 수 있다.

### M8. A&R 데모 수신함 (신규)
- 기능
  - 곡 리드 작성·발송(작곡가 주소록)
  - 데모 업로드 링크: 작곡가·퍼블리셔·크레딧 입력
  - **오디오 지문(Chromaprint)으로 중복 음원 탐지:** 형식·비트레이트가 달라도 같은 녹음을 잡아낸다. 2분 음원 기준 100ms 이내로 처리된다.
  - 청취 평가: 평점·태그·코멘트, 팀원별
  - 후보곡 보드: 검토 / 홀드 / 확정 / 반려
  - 홀드 요청 발송(승인 후)
- 한계: Chromaprint는 **거의 같은 음원**을 찾는 도구다. 표절 판단 도구가 아니다.
- 완료 기준: 곡 리드 1건에 데모 200곡이 들어와도 중복이 표시되고, 팀 평점순으로 추릴 수 있다.

### M9. 콘텐츠 제작·게시
- **원본:** 기획사가 보유한 파일만 쓴다. **YouTube 다운로드(yt-dlp)는 제거한다.** '채널 영상 목록'은 참고용으로만 두고, 원본 파일을 업로드하도록 안내한다.
- **YouTube 게시:** OAuth + Data API. 2026년 6월부터 업로드는 프로젝트당 하루 100건의 별도 한도로 바뀌었다. 기본 공개 범위는 '비공개/일부 공개'로 하고, 승인 후 공개로 바꾼다.
- **Instagram Reels:** 비즈니스 계정만 가능. 권한 두 개(`instagram_business_basic`, `instagram_business_content_publish`)에 각각 앱 심사가 필요하고 2~4주 걸린다. 계정당 24시간 25건 한도, 릴스 탭 노출은 5~90초 9:16 영상만 된다.
- **TikTok:** Direct Post는 심사 통과 전까지 모든 게시물이 '나만 보기'로 강제되고, 하루 5명까지만 쓸 수 있다. 심사에는 전체 흐름 시연 영상과 개인정보처리방침이 필요하다.
- 완료 기준: 원본 업로드 → 초안 → 승인 → YouTube 비공개 업로드 → 승인 후 공개가 한 흐름으로 된다.

### M11. 컴플라이언스
- **미성년자 (개인정보보호법 제22조의2)**
  - 생년월일로 만 14세 미만을 자동 판정한다.
  - 법정대리인 휴대폰 본인확인(PASS 등)으로 동의를 확인하고, 확인 전에는 프로필을 비공개로 둔다.
  - 동의하지 않거나 응답이 없으면 법정대리인 정보를 삭제한다(개인정보 포털 사례: 5일).
- **AI 기본법 (2026-01-22 시행)**
  - 고영향 영역에 '채용 등 권리·의무에 중대한 영향을 미치는 판단·평가'가 포함된다.
  - 오디션 심사 보조가 해당하는지 법률 검토가 필요하다.
  - 해당되는 경우에 대비해 위험관리 문서, 결과 설명(근거 표시), 사람의 관리·감독(승인 강제), 결정 기록을 설계에 미리 넣는다.
- **보존·삭제:** 불합격자 자료 보존 기간, 지원자 삭제 요청 처리, 실행 기록 마스킹
- **감사 로그:** 열람·다운로드·승인·발송을 기존 `audit_events`에 기록

## 5. 시스템 구조

```
[브라우저: 지원자 앱 · 기획사 콘솔 · 자동화 편집기]
      │  HTTPS (세션, 기획사 단위 권한)
[Next.js 앱 서버] ── Postgres (기존: users, tenants, audit… + 신규 테이블)
      │                    └─ 작업 대기열 (pg-boss 등, 같은 DB)
      ├─ 오브젝트 스토리지 (S3/R2) ← 브라우저 직접 분할 업로드(서명 URL)
      └─ 웹훅 수신 (Slack 버튼, 알림톡 결과, 플랫폼 콜백)
[작업자 서비스]
  ├─ 자동화 실행 작업자 (Node): 단계 실행, 재시도, 승인 대기·재개
  ├─ 미디어 작업자 (Python·ffmpeg): 트랜스코딩, 춤·음정 비교, 하이라이트, 오디오 지문
  └─ 발송 작업자: 알림톡·이메일·게시, 발송 결과 기록
```

**실행 엔진 선택**

| 선택지 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| Postgres 대기열(pg-boss 계열) + 자체 엔진 | Postgres가 이미 있음. 지원자 데이터가 외부로 나가지 않음. 현재 엔진 로직 재사용 | 스케줄·재개 기능을 직접 다듬어야 함 | **권장 (1단계)** |
| Inngest | Next.js·서버리스와 잘 맞음. 이벤트·cron·대기가 내장. 월 10만 회 무료 | 외부 서비스에 실행 데이터가 흐름 | Vercel 배포를 유지한다면 대안 |
| Trigger.dev | 오픈소스(Apache 2.0) 자체 호스팅, 긴 작업·체크포인트에 강함 | 별도 인프라 운영 | 영상 처리가 커지면 검토 |
| Temporal | 가장 강력한 내구 실행 | 클러스터 운영 부담이 큼 | 과함 |
| n8n 내장 | 기능이 많음 | Sustainable Use License상 **상용 제품에 넣으려면 유료 계약 필요** | 제외 |

**새 테이블 (요약)**

- `auditions`, `applications`, `application_events`, `evaluations`, `selftape_requests`, `share_links`

## 7. 출시 계획

IR 로드맵(현장 업무 확인 → 첫 실사용 → 반복 적용 → 유료 전환 판단)과 맞춘다.

| 단계 | 기간 | 만들 것 | 끝났다는 기준 |
| --- | --- | --- | --- |
| **1. 기반** | 0~6주 | M1 계정·권한, M2 서버 저장·분할 업로드, M6 서버 실행(직접 시작·새 지원서·재시도·실행 기록·자격 증명), M11 법정대리인 확인, **yt-dlp 제거** | 기획사 1곳이 로그인해 지원자 자료를 서버에 쌓고, 자동화가 서버에서 돈다 |
| **2. 파일럿 MVP** | 6~12주 | M3 공고·지원서, M4 자료 점검·평가표·셀프테이프·일괄 작업, M5 알림톡·일정, 승인 요청 Slack 전달 | 파일럿 기획사의 오디션 1회를 처음부터 끝까지 ENTER—AX로 운영 |
| **3. 반복 적용** | 12~20주 | M7 분석 비동기화, M10 지표, M4 공유 링크·블라인드, M8 데모 수신함, M9 YouTube 게시 | 기획사 3~5곳이 재사용하고, 검토 시간 전후 비교 데이터 확보 |
| **4. 확장** | 20주~ | Instagram·TikTok 게시(심사 후), 업계 자동화 템플릿, SSO·세분화 권한(엔터프라이즈), 비용 표시 | 유료 요금제별 기능 구분 완료 |

**요금제와의 연결 (IR 덱 기준)**
- Starter: 공고·심사·알림톡
- Growth: 자동화 편집기 전체, 팀 권한, 지표
- Enterprise: 권한 세분화, 외부 연동 맞춤, 보안 검토
